## 一、系统架构

```
浏览器 ──80──> nginx（唯一入口，动态解析上游）
                ├── /           前端静态页（Vue3 dist）
                ├── /api/       FastAPI 后端 :8000
                ├── /live/      ZLMediaKit :80（视频流同源反代）
                └── /view/      组态只读页
后端 ──> MySQL:3306（配置/用户/报警/画面）
     ──> Redis:6379（实时值 rt:{site} + 变化流 stream:changes）
     ──> TDengine:6041 REST（历史库 plant.samples）
网关 ──> Modbus 模拟器（端口由 SIM_PORTS 决定，默认 15020~15022，规模测试 15020~15039）
     ──> 实时值写 Redis；历史写 TDengine（5s 一批，带死区）；报警写 MySQL
     ──> ffmpeg 推演示流 rtmp://zlm:1935/live/mock1（断线自动重推）
```

**历史数据只由网关写**（网关持有全部实时值，避免后端再回读 Redis 造成双份写入）。
后端只读 TDengine。

视频鉴权（2026-11-07，任务 03）：

- ZLM 的 `[hook]` 已开启，播放/推流都回调后端 `/api/zlm/on_play`、`/api/zlm/on_publish`，**返回 `code=0` 才放行**（ZLM 自己的约定，不是 HTTP 状态码）
- 播放 token 由后端 HMAC-SHA256 签发，格式 `{exp}.{sig}`，**绑定 stream**，默认 5 分钟（`VIDEO_TOKEN_TTL`）
- 前端播放地址形如 `/live/cam01.live.flv?token=xxx`，由 `src/utils/live.js` 缓存并在到期前 60 秒自动续签；**前端不含任何固定密钥**（ZLM_SECRET 只在后端 `.env`）
- hook 地址只接受 ZLM 从容器内网直连 `backend:8000`；nginx 另有 `location /api/zlm/ { return 403; }`，外部调一律 403
- 手工验证：`curl 'http://127.0.0.1/api/video/token?stream=mock1' -H "Authorization: Bearer <token>"` 拿播放 token，拼到 `/live/mock1.live.flv?token=...` 才能拉到字节

真实相机配置示例（改完 `docker compose up -d backend`）：

```bash
VIDEO_CAMERAS={"S001":[{"name":"进水口","rtsp":"rtsp://your_user:your_password@192.168.1.60:554/cam/realmonitor?channel=1&subtype=0"}]}
```

- 大华：`/cam/realmonitor?channel=N&subtype=0`（主码流）/ `subtype=1`（辅码流）
- 海康：`/Streaming/Channels/101`（主码流）/ `102`（辅码流）

## 八点五、组态编辑器（P1：WinCC 式三栏）

路由 `/scada/editor/{画面id}`（列表页与画面树均可进入，模板画面也能编辑）。

布局与操作：
- 顶栏：画面名（点击改名）｜保存（Ctrl+S）｜撤销/重做（P2 实现，置灰）｜网格开关｜
  对齐工具组（P7 实现，置灰）｜预览（开只读页）｜返回平台｜**@CurrentSite 站点上下文**（P4 间接变量连接的依据，选择结果随画面保存）
- 左栏 240px：上「画面树」下「对象库」，分隔条可拖宽，宽度存浏览器 localStorage
- 画面树：公共模板 → 站点 → 站点独立画面 → 子画面；节点右键 =
  新建子画面 / 重命名 / 复制 / 锁定 / 设为模板 / 绑定到站点 / 删除；
  每行显示对象数量；顶部搜索框按名称过滤
- 对象库：标准对象 8 种、智能对象 6 种、工艺图元 11 种、控件 8 种，分组可折叠。
  **插入按 WinCC 官方交互**：选项板点选 → 光标变十字 → 画布单击一次落位（Esc 取消）；
  仅「符号库」支持拖放（抓手光标）
- 画布固定 1600×900 绝对坐标，按容器宽高自动等比缩放并居中（浏览器 100%/125% 都不裁切）
- 保存：Ctrl+S 或顶栏按钮；有未保存改动时切换画面/离开页面会先询问；
  锁定的画面保存被后端拒绝（403），需先在画面树解锁

### P2 画布交互（已实现）

- 选中：单击对象出现蓝色选中框 + 8 个控制点（四角+四边中点，7px 不随画布缩放变形）；
  Shift+单击 加选；空白处拖出选框圈选；点空白或 Esc 取消；多选时属性面板显示「已选中 N 个对象」
- 拖拽：按住对象内部拖动；网格开时吸附 20px、按住 Alt 临时取消吸附；
  超出画布贴边；拖动中左下角实时显示 x,y；松手才写入数据并入撤销栈
- 缩放对象：拖控制点改 w/h，Shift 锁定等比，最小 10px；
  水平管道只能改宽、垂直管道只能改高、T 形管/弯头尺寸锁定
- 键盘：方向键微移 1px（Shift+方向键 10px）、Delete 删除、Ctrl+C/V 复制粘贴（偏移 +20）、
  Ctrl+D 原地复制、Ctrl+A 全选、Ctrl+Z 撤销 / Ctrl+Y 重做（100 步命令栈，只存差异）；
  焦点在输入框时上述快捷键不生效
- 视图缩放：Ctrl+滚轮缩放画布；顶栏显示实际比例，点击可选 50%/75%/100%/适应窗口
- 性能：拖动只改 DOM transform（rAF 帧循环），200 个对象拖拽平均帧时间 ≈16ms（60fps）

### P3 属性面板（已实现）

- 面板结构（与 WinCC 一致）：顶部显示「类型名 + 对象序号」（如 液位罐 #1）与可编辑的
  对象名；页签 = 几何｜外观｜字体｜动态化｜事件（动态化见 P4，事件 P5 先放占位）
- **按对象类型分支**，不是万能表单：
  - 液位罐：5 页签全有；外观分「罐体 / 液体 / 其他」三组（填充色、液体色、液位方向等）
  - 管道（水平/垂直）：**没有字体页签**，外观 = 填充色 / 粗细 / 流动动画开关
  - 按钮：有「事件」页签、**没有「动态化」页签**（按钮靠事件动作）
  - T 形管 / 弯头：只有几何页签且只读（尺寸由图形决定），可整体拖动
  - 其余类型：几何 + 外观 + 字体 + 动态化 + 事件
- 编辑方式：
  - 数值字段可直接输入，也可**按住字段左右拖动**（每像素 ±1，Shift ±10）
  - 颜色 = 色板 + 十六进制输入框双向同步（#RGB / #RRGGBB）
  - 改任何字段**立刻反映到画布**（就地改样式，不重建画布——视频窗不会重连）
  - 非法输入：红框 + 提示，不写回数据；失焦后输入框还原为真实值
  - 多选时只显示共同字段，修改作用于全部选中对象；多选不可改名
- 属性修改入撤销栈（Ctrl+Z 可撤回）
- 对象命名：默认按类型编号（液位罐1、液位罐2…），可改名；
  **同一画面内名称唯一，且不能只靠大小写区分**，重名当场提示「名称已存在」
- 字段都带「可否动态化」标记（面板里 ◈ 图标）：运行时改了没效果的属性在 P4
  不显示动态化入口（官方 4.8.4.2：这些属性没有动态化图标）
- 背景图（外观页签）：上传 PNG/JPEG/WebP/GIF，≤5MB；存 `/opt/plant-data/uploads`
  （容器卷 /data/uploads，重建不丢）
- 面板可折叠：右上角 › 收起后画布撑满，左侧「属性」细条可再展开；
  窗口宽 <1400px 打开编辑器时默认收起（选择记忆在 localStorage）

### P4 变量关联（已实现）

术语全部照 WinCC 官方，不自创。五种机制：

| 机制 | 数据形态 | 说明 |
|---|---|---|
| ① 直接变量连接 | `{"mode":"tag","expr":"S001.LEVEL"}` | 变量值 → 属性 |
| ② 间接变量连接 | `{"mode":"indirect","nameExpr":"@CurrentSite + '.LEVEL'"}` | 变量名本身是表达式算出来的 |
| ③ 动态对话框 | `{"mode":"dialog",trigger,formula,dataType,ranges,other,evalTagStatus,evalQuality}` | 值域映射（Analog/Bool/Bit/Direct） |
| ④ 动画 | `{"mode":"animation",trigger,tracks:[{attr,ranges}]}` | 一个变量同时驱动多条属性，只能配在单个对象上 |
| ⑤ 直接连接（事件） | 挂在事件上 | P5 实现，P4 只留数据结构 |

`item.dyn` 两种写法都认：**单属性** `dyn:{mode,expr}`（目标属性按类型取默认）与
**多属性** `dyn:{"height":{...},"fillColor":{...}}`。面板一律写第二种（一个对象能挂多条），
读的时候兼容第一种（手写 json / 早期数据）。动画在运行时会被展开成「每个属性一条 binding」，
运行时只认一种形状，不为动画另写一套应用逻辑。

**求值引擎**（`frontend/src/scada/expr.js`，纯函数，先写引擎后做 UI）

- 自写词法分析 + 递归下降，白名单语法：变量引用、`@CurrentSite`、`@Tag()`、`@Quality()`、
  字符串拼接、四则/取模、比较、`&& || !`、三元 `? :`、字面量
- **不用 eval / new Function**（verify.sh 第 47 项守住：剔掉注释行后 grep 不到）
- 优先级：`? :` → `||` → `&&` → `== !=` → `> < >= <=` → `+ -` → `* / %` → 一元 → primary
- 裸变量名（无点号）自动补当前站点前缀；`&& / ||` 短路求值，右侧引用不存在的点位不会误报
- 统一返回 `{ok,value,quality,refs}`；失败返回 `{ok:false,reason}`，
  reason ∈ `tag_not_found / bad_number / syntax / empty / no_site`
- **数值转换失败绝不当 0**；`q=1` → `quality:'bad'`（界面按质量差处理）
- **求值结果缓存 200ms**（key = `站点|表达式`），一个 800 对象的画面每 250ms 广播一次，
  也不会把同一表达式重复算 800 遍；`cacheStats()` 可看命中率

**求值失败时的表现**（任务书硬要求）

属性**保持上一次的值** + 对象标黄（1px 虚线描边 `#f59e0b`），**绝不显示 0**。
上一次成功求值的值按「对象名|属性」记在画布容器上，画面重建（改结构、重绘）后还能放回去；
切站点时这份缓存会清空——否则换站后新站点缺点位会留着上个站点的数字，看着像"切站没生效"。
另外，已被动态化接管的属性，P1 就有的旧式 `var` 通道不再写它（一个属性只能有一个驱动源）。

**@CurrentSite**

优先级：URL 参数 `?site=` > 画面属性里的默认站点 > 全局当前站点。
切站点时整页重新求值，**不刷新页面**（`history.replaceState` 改地址栏，`__p4mark` 变量还活着）。
变量选择器里有「插入 @CurrentSite」按钮，不用手打。

**变量选择器**（20 万点位，禁止全量加载）

- 三级树：站点 → 设备 → 点位，点开哪级才请求哪级（`/api/sites`、`/api/devices`、`/api/points`）
- 搜索走后端 `GET /api/points?q=&site=&rw=&limit=50`，前端 **300ms 防抖**，
  返回 50 条 + `has_more`，底部「加载更多」翻页
- 绑按钮/输入框时只显示可写点位（`rw=1`）
- 最近使用 10 个（localStorage `scada.recentTags`），常用点位不用每次找

**动态对话框**：字段顺序照官方 4.8.4.4 ——
事件名称 → 表达式 → 结果 → 数据类型 → 评估变量状态 / 评估质量码 → 值域表 → **其他**。
`other` 必填，面板留空会橙字警告：没匹配到值时属性就取它，省掉会表现为超量程时数字消失/颜色变黑。

**动画**：多选时禁用（官方限制，面板显示「动态化只支持单个对象」）；
支持「复制动态化 / 粘贴动态化」把一套配置搬到另一批对象上；编辑器画布内直接可见预览，不用切运行态。

**闪烁**：用 Web Animations（`node.animate` 改 opacity），**不占用 CSS `animation` 属性**——
管道流动动画在用 `animation`，两者必须能共存。一个画布只有一个 250ms 全局定时器统一广播，
不是每个对象各自 setInterval。

### P5 事件（已实现）

事件键名照 WinCC 官方事件表，不自创；存进 `item.events`（键 = 事件名，值 = `{action, key?, gesture?, locked?}`）。

**事件清单**（五组）：

| 组 | 事件 | 说明 |
|---|---|---|
| Mouse | mouse.click / mouse.press.left / mouse.press.right / mouse.release.left / mouse.release.right | 鼠标 |
| Mouse | **mouse.leave** | 官方表里没有，本平台补的（UI 上标「补」）：Web 的 mouseup 绑在 document 上，按住拖出对象后 release 不会在对象上触发，瞬时按钮的线圈就永远停在 1 |
| Keyboard | keyboard.press / keyboard.release | 参数=按键名；F10 / Alt+Print 官方禁用 |
| Focus | focus.change | 焦点取得/切换（Tab、鼠标点击都可触发） |
| Miscellaneous | object.change / gesture / picture.open / picture.close | gesture 参数 = 长按(>600ms) / 滑动(>30px) / 双击 |
| Object attribute | `<attr>.change` | 任意属性变化，如 fillColor.change、value.change（与动态化同一套属性名） |

**动作类型**：一期只做 **Direct Connection**（官方定位：画面内最快、性能最高）。
VBS / C 动作在 UI 上列出但标「二期支持」，选中后运行时提示「当前版本请用直接连接」。

**直接连接**（源三选一 → 目标三选一，照官方 4.8.4.11）：

- Source：`{kind:"constant",value}` ／ `{kind:"attr",objectName,attr}` ／ `{kind:"tag",expr,sync}`
- Objective：`{kind:"window",attr}`（当前画面；attr 可为 bg / openPicture / closePicture）
  ／ `{kind:"attr",objectName,attr}` ／ `{kind:"tag",expr,sync}`
- 可选「输出操作员消息」→ POST /api/scada/oplog 落审计

**六个预设**（下拉首选，底层都落到上面的结构）：
setTag 置位 / resetTag 复位 / toggleTag 取反（读当前值→取反→写回，`op:"toggle"`）/
momentary 瞬时 / openPicture 打开画面 / closePicture 关闭当前画面。

**瞬时动作（任务书单条强调）**：默认绑三条 —— `mouse.press.left` 写 A、`mouse.release.left` 写 B、
`mouse.leave` 写 B，三条都带 `locked:"momentary"`，**leave 不允许删也不允许改**，否则按住拖出按钮再松手线圈会停在 1（现场表现=泵停不下来）。

**按钮四种行为 = 事件组合**（不是模式）：置位 = release.left→setTag(1)；复位 = release.left→setTag(0)；
切换 = release.left→toggleTag；瞬时 = press(1) + release(0) + leave(0)。

**写回链路**（每个写动作都走这条）：

1. 校验：绑定后批量 `POST /api/scada/resolve` 拿 rw；rw=0 → 对象加 `scada-ro`（半透明 + 「只读」角标 +
   悬停提示「只读点位」+ 内部 button disabled），点击再拦一层
2. 写：POST /api/write {site, point, value} —— viewer 403、只读 400、不存在 404
3. 回读：网关写完 200ms 读寄存器，不一致返回 409「写入失败：回读为 X」
4. toast：成功「已写入 1」；回读不一致/超时「写入超时，请检查网关」红色
5. 审计：sys_op_log 记 谁/何时/哪个点/原值/新值/IP/result（ok / fail:mismatch / fail:timeout / fail:gw / fail:gw_down）
6. 防连点：同一对象 300ms 内不重复提交，且上一次请求没回来之前不再提交

**事件表 UI**（照官方 4.11 布局）：左侧树 Mouse / Keyboard / Focus / Miscellaneous / Object attribute，
右侧表 = 事件名｜动作（● 有动作 / — 无）｜参数（按键名 / 手势）｜**测试按钮**（不切运行态直接触发一次）。
双击「动作」列弹出动作配置（预设 → 源三选一 → 目标三选一 → 操作员消息）。整块 events 提交，Ctrl+Z 可撤回。

**编辑态与运行态的边界**：编辑器里点对象是选中，**鼠标/键盘动作不执行**（不能在编辑器里顺手写现场）；
但「测试」按钮走 `testEvent` 直接执行一次。picture.open 也只在运行态触发——否则打开编辑器就写 PLC。
运行态触发计数写在节点 `data-ev-count` 上，验收和排障都看它。

#### 报警窗：为什么必须是 SSE

轮询 5 秒的后果是操作员看到报警时已经过去 5 秒——报警窗不能这么干。链路：

1. `alarm_engine` 在 raise / update / recover / ack / close 五处 commit 之后 `_push(a, act)`
2. `core/realtime.py` 的 `publish_alarm()` → `XADD stream:alarms MAXLEN≈5000`（推送失败只吞异常，报警已经落库）
3. `GET /api/alarm/subscribe?site=&scope=&token=` → SSE：**先取游标再推 snapshot**（顺序反了会丢事件），
   然后 `event: alarm` 增量，15s 一次 `event: keepalive`
4. 生成器里的 DB 查询走 `asyncio.to_thread(_snapshot_sync, ...)` 且**自开 `SessionLocal()`**（Session 非线程安全）

token 走 query 参数——`EventSource` 带不了 Header。

#### 视频窗四个坑（现场踩过的）

1. **必须同源走 `/live/`**：浏览器里跨源播 ZLM 会 CORS 白屏，地址一律由 `/api/video/url` 下发
2. **flv.js 错误回调只有 `NETWORK_ERROR` / `MEDIA_ERROR` 才重建**：一律 destroy 会变成「建了销毁、销毁又建」的死循环，
   表现是黑屏 + 控制台刷屏且**没有任何报错**
3. **失败必须显示具体原因**（「视频流已中断（10 秒没有数据）」），不许黑屏了事
4. **H.265 播不了**：相机侧改 H.264，或 ZLM 开转码

另外两条：**主辅切换先 stop 再 play**（先 play 会拿到旧流）；watchdog 2s×5 没有 `currentTime` 推进即判断流，
之后受控重试 5s 一次、最多 12 次（实测 t+12s 报错 → t+18s 自愈）。

主辅流靠真实分辨率区分：演示流推两路 `mock1`（1280×720）与 `mock1_sub`（640×360），
token 侧先剥 `_sub` 再取站点（否则 `S001-1_sub` 被当成站点 S001-1 → 403）。

2. 左上角显示控件类型标签 `class="scada-ctl-tag"`，运行态隐藏

#### 对齐与分布：先取绝对坐标，落点一律 Math.round

- 单选 → 相对画布六种（`canvas-l/r/t/b/hc/vc`）；多选 → 六种互相对齐（`l/r/t/b/hc/vc`）
- 基准默认「**最后选中的对象**」，顶栏下拉可切「以最外层包围盒为准」（`alignBase = 'last' | 'bbox'`）
- 组内子对象参与对齐时用 `absOf()` 取绝对坐标，写回时 `localOf()` 减组原点
- **落点必须 `Math.round`**：1600/2 = 800 没问题，但 900/2 或组宽是奇数时会出现 .5，坐标带小数会“跳一下”
- 等距（`distributeRects`）保持**首尾两个不动**，间距可能算出负值也照排（重叠时也不报错）

实测（`check_p7.py` 1a/1b/2）：三对象左对齐后 `x={'甲':420,'乙':420,'丙':420}`，切包围盒基准后 `x` 全 = 100；
五对象等距间距 `[70,60,110,140] → [95,95,95,95]`，坐标 `x=[40,235,390,565,700]`（首尾未动）。

#### 图层：items 数组顺序就是 z-index，不另设字段

- `json.layers = [{id,name}]`（官方 4.5.13 图层带），对象用 `item.layer` 归层，新建对象落**当前层**
- 列表显示时 `reverse()`：数组末尾 = 顶层 = 列表第一行；拖拽排序只改数组顺序（`reorderByIndex`），**不写 z-index 字段**
- 锁定 `item.locked = true` → `render.js` 给节点 `pointer-events:none`，画布点不中、拖不动，但仍渲染
- 隐藏 `item.hidden = true` → `render()` 直接 `return null`，**数据保留在 json 里**（保存后仍在）
- 上限 32 层：`＋` 按钮到 32 仍可点，点了给提示「图层最多 32 层（官方限制），已经满了」（不 disable，否则用户永远看不到提示）

#### 组合：子对象存相对坐标，嵌套限深 20

- json 形态 `{ type:'group', x,y,w,h, items:[…] }`，**子对象的 x/y 是相对组原点的**
- 进文件时 `absOf()` 加成绝对坐标，写回时 `localOf()` 减掉组原点 —— 拖 100 次不累积误差
- 路径寻址：`data-idx` 从整数改成路径字符串 `"3"` / `"3.i.0"`（`i` 只是分隔符），`render.js` 用 `paths: Map(item→path)` 反查
- `_resolveNode()` 向上找 `data-gpath`：默认选**最外层组**；`editPath` 等于该组的 gpath 时才允许选子对象（即“双击进组”）
- 双击组 → `enterGroup()`（顶栏出现「正在组内编辑「X」…Esc 退出」），`Esc` 先退组；组缩放走 `cmdGroupResize`，一条命令同时回退组框与全部子对象

#### 参考线：5px 吸附，松手即消失

- 拖动时与其余对象比三锚点（起边/中心/止边）× 两轴，各取最近的一条，阈值 `SNAP_PX = 5`（**不是 10**）
- 命中后画 `.guide-line`（红线）+ `.guide-label`（距离 px），最多 6 组；**竖线标 y 方向空隙，横线标 x 方向空隙**
- 只在拖动（`drag.started`）期间存在，`_onUp` 里 `_clearGuides()`；按住 **Alt** 临时关闭吸附
- 参考线层必须 `pointer-events:none`，否则会挡住自己的拖拽

### P8 组件模板 / 值列表 / 列表页 / 一键铺站（已实现）

#### 三条硬约束（写死，后人别改回去）

1. **实例只存 `fptId` + `bindings`，绝不拷贝模板 json** —— 拷贝了「改模板所有实例同步变」立刻失效
2. **缩略图存文件**（`/opt/plant-data/thumbs/{id}.png`），不 base64 塞 json —— 否则 200 张画面把 page 表撑爆、列表页越开越慢
3. **铺站必须能预览**（每站替换几处 / 几个点位在目标站不存在），执行前看得见

#### 数据模型

| 表 | 字段 | 说明 |
|---|---|---|
| `faceplate` | `id / name / w / h / json / iface / locked / updated_at` | 组件模板本身（官方 4.6.1 的「类型」） |
| `valuelist` | `id / name(unique) / kind(text\|graph) / items / updated_at` | 文本列表 / 图形列表（官方 4.7） |
| 画面 json | `{ "type":"faceplate", "fptId":7, "x":120, "y":200, "bindings":{"PV":"S001.LEVEL","RUN":"S001.PUMP1_RUN"} }` | 实例（官方 4.6.1 的「实例」） |

接口变量存 `iface = [{name,type,default,desc}]`，类型 `real/bool/int/string`；模板内部对象用 `@PV` / `@RUN` 引用。
变量名规则 `^[A-Za-z_][A-Za-z0-9_]{0,15}$`，且 **`@CurrentSite` 是运行时关键字，不能占用**（后端 400，前端先拦一遍）。

#### 渲染：每次展开，不缓存

`render.js` 的 `type === 'faceplate'` 分支：

- 从 `handlers.fpt`（运行时 `Map`，由 `GET /api/fpt?full=1` 一次拉全）取模板；取不到画红虚线「组件模板 #N 不存在」
- `sizeOf(def)` 得模板原始尺寸，容器 `transform:scale(w/tw, h/th)` + `transform-origin:top left`（模板按自己的 200×200 排版，实例随便缩放）
- `expandInstance()` 把 `@PV` 换成 `bindings.PV`（没绑定回落 `iface.default`）**每次渲染都重新展开**
- 子对象必须同时进 `st.items`（`styles.push({ kid:true, … })`），否则 dyn.js / events.js / 控件订阅遍历不到 —— **模板里的液罐和灯就永远不动**（这是 P8 最容易踩的坑）

#### 缩略图：前端 canvas 画 400×225 PNG

`src/scada/thumb.js` 的 `paintThumb(json, {fpt})`：按 json 画形状 + 文字（液位罐画 45% 液位、圆/椭圆、管道/输送带矩形、其他圆角矩形），
组件模板实例会**展开模板再画**（否则列表里凡是实例画面只剩两个虚线框）。
保存画面后 `uploadThumb()` → `POST /api/page/{id}/thumb`（base64）→ 后端校验 PNG 魔数 → 原子写 `/data/thumbs/{id}.png`；
列表页 `<img src="/api/page/{id}/thumb.png?v=更新时间">`，**这个 GET 是公开的**（`<img>` 带不了 Authorization）。
删画面时顺带删缩略图文件。

> 为什么不用 headless chromium：200 站点每次保存都起一次浏览器太重；为什么不用 html2canvas：多一个依赖且 SVG 序列化会被 tainted canvas 挡住。

- 批量：勾选后出现「批量删除 / 批量复制到站点…」；组件模板不允许铺站（提示「所有站点画面共用它」）

#### 一键铺站

`POST /api/page/{id}/spread/preview` → 逐站返回 `{site, site_name, name, replaced, indirect, invalid, invalid_tags, exists}`；
`POST /api/page/{id}/spread` 执行（`overwrite` 可选覆盖）。

- 替换规则：深度遍历 json 字符串，`src_site + '.'` → `dst_site + '.'`
- **含 `@CurrentSite` 的字符串跳过不换**（并计入 `indirect`）—— 换了就等于把「跟随当前站点」写死成某一站，铺站后数值全空
- 命名占位符：`{name}` 源画面名、`{site}` 站点编号、`{site_name}` 站点名
- 预览阶段一次性查完目标站点全部点码（不在循环里查 200 次），`invalid_tags` 列出目标站缺哪些点位
- 生成的画面 `template_id` 指向源画面 → **删源画面会被 409 挡住**（「还有 N 张子画面」），要先删子画面

#### 删除组件模板的引用检查（别用 LIKE）

`DELETE /api/fpt/{id}` 先扫画面 json，`_uses_fpt()` 递归找 `type=faceplate && fptId==id`，有引用返回 **409**。
不要写 `Page.json.like('%"fptId": %d%%' % fid)`：`%"` 会被 Python 当格式符直接抛 `ValueError`（删模板恒 500），
且 `%fptId": 1%` 会把 `fptId: 12` 也算成引用。

**跑这一册时修掉的两个真缺陷**（不是脚本问题）：

1. **动画的数值轨道被"其他"颜色污染**（`dyn.js`）
   动画高度轨道在最后一档之外拿到的是 `other`（面板上它填的是颜色 `#7f8c8d`），

   修法：`NUMERIC_ATTRS`（height/opacity/value/blink/angle）+ `edgeValue()`，未命中区间时**夹到端点档位值**。

2. **瞬时按钮偶发停在 1**（`events.js`）
   两处叠加：① `mouseup` 只挂在对象节点上，按住拖出去松手落在 document，对象收不到；
   ② 松开那一下撞上"上一条写还没回来"，被防连点直接丢掉，且没补救。
   修法：按下记账（`__armedL`）+ 画面级 document `mouseup` 兜底；写被挡时记 `__pending`，上一条回来立刻补发。

3. **演示流越推越乱**（新增 `gateway/stream_ctl.sh`）
   gateway 是 alpine 底，容器里**没有 `pkill`/`pgrep`/`ps`**，之前验收脚本里的
   `pkill -f mock_stream.sh` 一路静默失败（还被 `2>/dev/null` 吞了），每跑一遍多留一对 ffmpeg，
   同名流互相踢 → 视频窗一会儿有一会儿没。现改为扫 `/proc` 自己 kill：
   `docker exec plant-gateway sh /app/stream_ctl.sh stop|start|status`。

### 二、缺陷二：I/O 域三模式

原状：`value` 控件只有「文本显示」一种形态，输入型对象要么做成只有显示、要么根本没输入框，没有 WinCC 那套 Input/Output/Input-Output。

现在照 WinCC 分三种 `mode`：

| mode | 表现 | 用途 |
|---|---|---|
| `output` | 只读 `<span>`，实时刷新 | 纯显示（等同原来） |
| `input` | 空 `<input>`，**实时刷新不覆盖**，提交后保留键入值 | 一次性录入（配方/设定值下发） |
| `inputoutput` | `<input>` 里是实时值，可改可提交 | 就地改设定值（现场最常用） |

改动点：

| 文件 | 改动 |
|---|---|
| `backend/app/api/sites.py` | 快照每个点位带 `rw` / `dtype`（前端凭 `rw` 判只读、给悬停提示，不等后端 400） |
| `frontend/src/scada/runtime.js` | `fullTag()` 裸名自动补当前站点（`LEVEL` → `S001.LEVEL`，手填 `S002.LEVEL` 原样用）；`rwOf(tag)` 取值里存的 `rw` |
| `frontend/src/scada/props.js` | `TABS` 加「输入输出」页签；`value` 新增 `mode`/`submitBy`/`inputMin`/`inputMax`/`showUnit`/`confirmWrite`；导出 `isLegacyVar()` 判旧格式 |
| `frontend/src/scada/PropPanel.vue` | 旧格式顶部黄条 + 「升级此对象 / 升级整张画面（N 个）」；数值字段支持 `nullable`（留空不报错） |
| `frontend/src/scada/render.js` | `case 'value'` 扩成三模式：真 `<input type="text" inputmode="decimal">`、非数字字符过滤、范围校验红框、Esc 回滚 / Enter 提交、成功闪绿失败闪红；`evalTagExpr()` 解 `@CurrentSite + '.X'` |
| `frontend/src/scada/ObjectPalette.vue` | 两个入口：「I/O 域（仅显示）」`mode:output`、「I/O 域（可输入）」`mode:inputoutput`（不做三个入口，用户会困惑） |
| `frontend/src/views/ScadaEditor.vue` | `makeItem`/`onDrop` 透传 `mode`；新增 `site`/`readValue`/`rwOf` handlers 与 `onUpgrade(list)` 批量升级（走 `ci.applyProps`，入撤销栈）；`onWrite` 返回 Promise |
| `frontend/src/views/ViewPage.vue` | 同步三个 handlers，`onWrite` 返回 Promise |

几个必须知道的实现细节：

- **不用 `type=number`**：浏览器对空值、小数点、滚轮滚值行为不一致，统一 `type="text"` + `inputmode="decimal"` 自己过滤。
- **`input` 模式的刷新必须跳过**：`patch = () => { if (mode !== 'input') renderVal(readLive()) }`。不跳过的话每 250ms 一次实时推送就把「空输入框」填成过程值，这个模式跟 `inputoutput` 就没区别了（首版踩过）。
- **输入框与实时刷新打架**：`document.activeElement === inp` 时跳过实时写值；但「写入失败回滚」和 Esc **必须 `force=true`** 绕过这个保护，否则回滚被自己的保护挡住（这个坑踩过）。
- **`el(tag, style, text)` 第二参是内联样式**，class 要单独 `x.className = '...'` 赋，别当第二参传（写成 `el('div','scada-io-tip')` 会定位不到元素）。
- **只读点位双保险**：前端 `rw=0` → 禁用 + 悬停提示；后端 `/api/write` 再拦一道返 400。

### 一、FX3U-ENET-ADP（MC · 1E 帧）

| 事实 | 说明 |
|---|---|
| **只支持 A 兼容 1E 帧** | 202 页手册「1E」出现 4 次、「3E」0 次。pymcprotocol 按发 3E 帧会被 ADP **静默拒绝**（真值 2.653 读回 [0,0] 不报错）——FX3U 设备绝不能走 pymcprotocol |
| **每个 MC 口只认一个连接** | 3 个 MC 连接（本机配置 4999/5000/5001）+ 1 个 MELSOFT（5556，留给 GX Works2）。采集长连接占一个口后，**同口再连就是 0 字节响应**——测试连接会自动换口试 4999/5000/5001（响应带 `port` 字段说明用了哪个口） |
| **连接纪律（用户明确要求）** | 每次只开一个连接，测完必须 close。采集=一条长连接；失败关连接+**指数退避**（5s→10s→…→30s），绝不每秒重连——2026-11-09 实测每秒重连几分钟就把槽打满，谁都连不上 |
| 1E 帧结构 | 副标题(00位读/01字读/02位写/03字写) + PC号FF + 定时器(L,H) + 起始编号4字节**小端** + 软元件名(空格+字母，D=`20 44`) + 点数2字节 |

| 支持软元件 | 字：D/W/R/Z/T/C（当前值）；位：X/Y/M/L/S/B。块规划字≤64点、位≤256点 |
| **协议参数里的「帧格式」** | 可选 `1E / 3E / 4E`，**FX3U/FX3G 必须是 1E**。选系列时会自动刷（`protocolSchema.js` 的 `mc.seriesDefaults`）：FX3U/FX3G→1E，FX5U/Q/L/iQ-R→3E。网关分派也看它：`mc_use_1e(series, proto_params)` —— 系列是 FX **或** frame=1E 都走 1E 驱动，现场只改协议参数也能生效（设备 225 已置为 1E） |

### 二、S7-200 SMART（S7comm · 102）

| 事实 | 说明 |
|---|---|
| V 区 = **DB1**，偏移=V 地址号 | VD1000 → `db_read(1, 1000, 4)`；rack0/slot1；端口 102 |
| **连接类型 PG / OP / S7basic 必须可选** | 三者的远程 TSAP 不同（PG=0x0100+、OP=0x0200+、S7basic=0x0300+rack*0x20+slot）。2026-11-09 实测：同一台 PLC 上 **PG 连接被直接 RST**（`Connection reset by peer`，无任何 COTP 回应），**OP / S7basic 都能连上并读到 DB1.DBD1000=32.768**。驱动按「首选 → OP → PG → S7basic」自动回退，并把实际用的类型回给前端（`conn_type` 字段），回退时附 `note` 说明。协议参数里的「连接类型」默认 **OP** |

| 0x8104 容错 | 200SMART 不支持 CPU 信息查询，snap7 某些版本 connect 内部会调它报 0x8104；驱动捕获后 `get_connected()` 二次确认 |
| **旧实现的致命坑（已修）** | `_test_s7` 把 `pdu_size=480` 传给了 `Client.connect` 的第 4 参——**那是 TCP 端口**，所有 S7 测试连接实际都在连 480 端口，所以「填 VD 没反应」；另有 `snap7.type` 在 3.x 不存在（M/I/Q 直接崩）、浮点小端解三坑，全部按 skill 重写 |

### 一、心跳：两种模式，一个状态机

site 表新增 6 列（`ALTER` 已打进 backend 镜像的迁移）：

| 列 | 默认 | 含义 |
|---|---|---|
| `heartbeat_mode` | `none` | `none` 不判定（沿用采集成功/失败，老行为）/ `modbus_echo` / `ping` |
| `hb_write_addr` | 0 | 回环写地址（**Modbus 0-based**：40001 → 0） |
| `hb_read_addr` | 1 | 回环读地址（40002 → 1） |
| `hb_max_value` | 2000 | 写入值循环上限 1~2000 |
| `hb_cycles` | 3 | 连续失败几次判离线，1~10 |
| `ping_interval_ms` | 5000 | ping 间隔 1000~60000 |

两种模式的差别（选错会得到「网络通但不知道 PLC 死活」的假在线）：

- **`modbus_echo`**：每轮写 `hb_write_addr = N`、读 `hb_read_addr` 比对，相等才算在线。一次动作同时证明三件事——TCP 通、**PLC 在 RUN**（停机时程序里的 MOV 不执行，读回旧值）、数据区可写。只对 `modbus_tcp` 有效；在别的协议站点上选了它，后端保存时**自动降级成 `ping` 并返回 `warning`**。
- **`ping`**：按 `ping_interval_ms` 探测网络；「健康」要求 **ping 通 + 本轮采集成功** 两个条件同时成立（只要 ping 通不等于 PLC 在跑）。
- 两个地址**不能相同**（同址写读永远相等，等于假在线），保存时直接 400。

状态机（`gateway/heartbeat.py` 的 `StatusMachine`，纯逻辑、可单测）：

```
unknown ──成功──> online ──1 次失败──> suspect ──连续 hb_cycles 次失败──> offline
                     ↑                                                      │
                     └──────────────── 任意一次成功 ─────────────────────────┘
```

- **只在状态变化时**回写，避免每轮 `UPDATE site` 打爆 MySQL：`site.status`（1 在线 / 2 离线）+ Redis `site:status:{id}` + 事件流 `stream:status`（`xadd`，maxlen 1 万，给前端推送用）。
- `hb_state`（`online/suspect/offline/unknown`）随 `/api/sites` 列表一起回给前端，页面上的「心跳」列看这个，不看 `status`。
- `hb_cycles` 传 0 或负数会被夹到 1（宁可快速判离线，不要永不判）；传空/非数字回落 3。
- 网关镜像已装 `iputils-ping`（alpine 默认没有 `ping`）；万一二进制缺失，`ping_host()` 退化成 TCP 连 502，只证明网通——所以能选 `modbus_echo` 就别选 `ping`。

配置位置：站点编辑页 → 心跳判定（选 `modbus_echo` 才出现写/读地址两栏；选非 `none` 才出现判定周期数）。接口保存示例：

```bash
curl -X PUT http://192.168.1.100:8091/api/site/S002 -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' \
  -d '{"heartbeat_mode":"modbus_echo","hb_write_addr":0,"hb_read_addr":1,"hb_cycles":3}'
# {"ok":true,"id":"S002","warning":""}    ← warning 非空说明发生了降级
```

### 二、站点测试：先用临时参数试，通了再落库

改 PLC 参数最怕「改一次存一次，存错了整站掉线」。所以测试接口**默认不碰数据库**：

| 接口 | 用途 | 关键点 |
|---|---|---|
| `POST /api/site/{id}/test` | 用 body 里的临时参数测，body 优先于已保存值 | 不写库；`addr`/`dtype` 不传就取该站第一个启用点位当样本；同站并发测试返回 **409**（PLC 连接数宝贵） |
| `POST /api/site/{id}/test/apply` | 把测通的参数写回站点并热加载 | 只写 `protocol/ip/port/rack/slot/slave_id/timeout_ms`，返回 `changed` 差异；不传的字段不动 |
| `POST /api/site/test` | 新建站点时表单现填现测（站点还不存在） | 参数原样转发网关 `/api/testconn` |

### 三、历史：五维查询 + 两个删除入口

**查询** `GET /api/history?site=S002&point=LEVEL&year=2026&month=11&day=10&hour=14`，维度决定区间与粒度：

| 给了哪些维度 | 区间 | 粒度 |
|---|---|---|
| 只有 `year` | 该年 1-1 00:00 ~ 次年 1-1 | 1d |
| `year+month` | 该月 1 日 ~ 次月 1 日 | 1d |
| `year+month+day` | 该日 0 点 ~ 次日 0 点 | 1m |
| `year+month+day+hour` | 该小时整点 ~ +1 小时 | 1s |

- 聚合一律 `interval(粒度) fill(none)`——**空档不补 0**，曲线断点就是断点，不能拿 0 冒充。
- 单序列 **2000 条**上限：按秒查 1 小时最多 3600 条，超过就自动降 **5s** 并在 `note` 里说明（`downgrade_gran` 是纯函数，单测直接调）。
- 不传 `point` 时**该站点点位超过 20 个直接 400**（防止一次拉回几十万条）；多序列用 `partition by point`，每条超 2000 截断并给 `note`。
- 不传 `year` 走老入口（组态趋势控件用），语义保持原样：必须给 `point`，支持 `minutes`/`from_ts`/`to_ts`/`interval`。
- 日期不存在（2 月 30 日、13 月）返回 400「日期不存在」，不是 500。

**删除** `DELETE /api/history`（admin only，必须 `confirm=1`）：

| 用法 | 效果 |
|---|---|
| `?site=S002&point=LEVEL&date=2026-11-01&confirm=1` | 删该点位那一天的数据行 |
| `?site=S002&point=LEVEL&keep_days=30&confirm=1` | 只保留最近 30 天，更早的全删（`keep_days` 最小 **7**，防止手滑删光） |

- **只删数据行，不删子表**：表结构留着，之后采集照写；子表本来就不存在（没开存历史）返回 `deleted_rows=0` + `note`，不当 500。

### 五、变量只认 `{site, point}`，I/O 域与重命名

- 变量新格式：`{"var":{"site":"S001","point":"LEVEL"}}`。**字符串、表达式一律判非法**——旧写法（`LEVEL`、`@CurrentSite.LEVEL`、`S001.LEVEL`）在渲染期直接不取值、保存期报错（`varbind.js` 的 `isValidVar`，verify 144 守住）。校验按 `trim` 后判空，`point:'  '` 这种空白不算合法（否则会拼出 `S001.` 这种坏 tag，这个 bug 是单测抓到的）。

- 图层/对象重命名支持**全部类型**（双击改名），重名自动加 `(2)`，可撤销（verify 145）。
- 属性面板的「旧格式黄条」不再提供「升级成 `@CurrentSite` 表达式」——表达式本身就是被禁的旧格式，黄条只引导重新选点位。
